# ToneCore v0.19.0

> 图标重做为圆形灰底；首页加歌单与推荐；音源状态默认显示；入库可选音质；修复续播不还原进度。

## 修复：续播不还原进度

### 现象

划掉页面短时间回来能续播，但**从头开始**；久了直接显示「未有曲目播放」，
像是记录丢了。

### 根因（三个洞叠加，只修一个都还是坏的）

| # | 问题 | 后果 |
|---|---|---|
| 1 | `init()` 恢复队列但**不恢复 `currentTime`** | 续播从头开始 |
| 2 | 进度**只写不读**：`saveProgressNow()` 调 `/api/v1/progress`，<br>但前端**从未调用** `v1GetProgress` | 写了也白写 |
| 3 | 队列与位置都是**纯内存态**，无落盘 | 重启/重建后队列归零 |

### 修法

- `PlayerService` 增加 `positionMs`，随队列一起落盘到 `data/player-state.json`；
- 落盘挂在 `touch()` 这一统一入口上 —— 否则以后新增改状态的入口就会悄悄退化回内存态；
- 新增 `/api/player/position` 上报；
- `init()` 恢复位置，并在 `loadedmetadata` 后把 audio 元素定位到续播点
  （元数据没加载完时直接设 `currentTime` 会失效）；
- SongLoft 兼容进度表照旧写入，供跨设备续播。

> `playUrl` 刻意不入库：上游直链会过期，每次启动重新解析。

## 新增

### 首页聚合接口 `/api/home`

首页原本要分别打 library / playlists / stats 三个请求，串行叠加首屏延迟，
且各自 loading 容易让板块错位跳动。改为一次拿齐：
歌单、最近入库、专辑/歌手分类、统计。

### 入库音质选择

点「入库」先弹格式选择（无损 FLAC / 母带 24bit / 320k / 128k），
选定后按该音质取链落盘并刮削。**试听不落盘**，不受影响。

⚠️ 取值必须与服务端 `QUALITY_WHITELIST`
（`master/flac24bit/flac/320k/128k`）严格一致，否则会静默回落成全局默认音质，
表现为「选了格式但没生效」。

## 变更

### 图标重做

旧版是「圆角方块 + 天蓝渐变 + 白色音符」，在同类音乐容器里辨识度低，
方形在 Unraid 面板与浏览器标签页里也显得笨重。

新版改为**正圆**：

- 底：石墨灰径向渐变（#565D66 → #22262C），有体积感也不撞色
- 顶部一道极淡高光，制造抛光质感
- 中心音符用主色青蓝（#4FC3F7→#35A9E8），与灰底形成冷暖对比
- 左右各一道声波弧（#2E9BE8），呼应「音源 / 声波」语义

同步覆盖 `assets/icon.svg` 与 `assets/icon.png`。WebUI 标签页、登录页、
设置页、侧边栏、README 引用的都是同一个文件，改一处即全站生效。

### 首页布局

歌单移到首页（跟随主流音乐平台做法），并增加「最近入库」「专辑」「歌手」
推荐分区。搜索时推荐让位给结果，避免干扰。点分类推荐落到本地检索。

### 音源状态默认显示

此前界面只在 `s.test` 存在时才显示状态，而 `s.test` 只有手动点「测试」
才会产生 —— 于是看起来像「不手动测就没有状态」。

改成默认用后端一直在累计的健康度（`healthDetail` 的 success / failure /
consecutiveFailures）判定并着色，手动测试的结果作为补充叠加。

⚠️ `healthDetail` **没有 `total` 字段**，总数要用 `success + failure` 算。
