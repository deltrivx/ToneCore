# ToneCore v0.33.1

> 修复封面补齐的匹配顺序 bug（先归一化把括号删了，导致「截掉版本后缀」失效），覆盖率 15% → 85~100%。

## 这是个什么 bug

v0.33.0 里我加了「按主标题匹配」来对齐酷我的版本后缀 —— 例如把
`稻香 (完整版|DJ Ray版)`、`稻 香（堵桥版）` 都归一到 `稻香`，好去匹配网易那边干净的 `稻香`。

但实现写成了：

```ts
const base = (s) => {
  const t = norm(s);          // ← 先归一化
  const i = t.search(/[（(]/); // ← 再找括号
  ...
};
```

**`norm()` 会把 `（）()` 当标点一并删掉**。所以等它执行完，字符串里已经一个括号都没有了，
后面那句 `search` 永远找不到 —— `base()` 退回返回整个字符串。

结果：**改进写进去了，但完全没生效**。

## 修正

顺序反过来 —— 先截括号，再归一化：

```ts
const base = (s) => {
  const raw = String(s || '');
  const i = raw.search(/[（(]/);
  return norm(i > 0 ? raw.slice(0, i) : raw);
};
```

## 教训

v0.33.0 是**改完就发、没有验证覆盖率**。而新旧逻辑跑出来的数字完全一样（都是 15%）
——这种「改了等于没改」，只有拿真实数据做前后对比才能发现。

这次补了验证：用 4 个关键词各 20 首真实数据跑新旧对照，确认提升后才发。
