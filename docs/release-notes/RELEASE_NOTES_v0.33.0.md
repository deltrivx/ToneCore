# ToneCore v0.33.0

> 更正 weapi 空响应根因（是我加密写错，不是通道不通）；登录后的 eapi 取链接入音源引擎；酷我无封面改用网易云补齐。

## 一、更正：weapi 空响应体是我自己的锅

v0.32.0 里我记了一条结论——「weapi 通道在本项目不通，故改用 eapi」。**这条结论是错的**，这次更正。

### 真因

NEMbox 的 `create_key()` 是：

```python
def create_key(size):
    return binascii.hexlify(os.urandom(size))[:16]
```

**先转十六进制字符串，再截 16 位** —— 得到的是 **16 个 ASCII 字符**（如 `"a3f2..."`）。

我却写成了：

```ts
const secret = crypto.randomBytes(16);   // 16 个原始随机字节
```

两者位数都是 16，但**字节内容不同**，服务端解不出 secret，于是
**静默返回 HTTP 200 空响应体** —— 状态码看着完全正常，所以极难发现。

### 决定性对照（同一台 Unraid、同一个接口）

| 载荷 | 结果 |
|---|---|
| secret = 16 个 ASCII 十六进制字符（NEMbox 同款） | ✅ 拿到 unikey |
| secret = 16 个原始随机字节（我原来的写法） | ❌ 体长 0 |

### 顺带更正另一条错误

v0.32.0 里我还记了「IPv4/IPv6 都返回 0」——那次用的是**假载荷**（`params=x`），
返回 0 是正常的，**该结论同样不成立**。

### 教训

「HTTP 200 + 空响应体」这种失败形态，绝不能只看状态码就下"通道不通"的结论。
必须拿**一份已知可用的载荷**到同一环境跑对照，才能区分「对方不给」和「我发错了」。
（这次正是靠把飞牛容器里能成功的载荷拿到 Unraid 上跑，才定性的。）

## 二、登录后的 eapi 取链真正接入音源引擎

这是个**真缺口**：v0.32.0 的 `NeteaseClient` 只挂在路由层，
也就是说**即使你扫码登录了，取链质量也不会有任何提升**。

现在 `getUrl()` 对 wy 平台的链路是：

```
已登录 → eapi 取链（有机会拿更高音质）
       ↓ 失败 / 未登录
       自研直连（wy-url.ts）
       ↓ 失败
       洛雪音源脚本
```

音质按 `levelForQuality()` 映射到网易的 level（flac→lossless、320k→exhigh 等），
并**回读实际 br/type** 判定真实音质 —— 未登录时要无损会被静默降级成 320k，
不回读就会谎报。

## 三、酷我无封面 → 用网易云补齐

实测搜「稻香」：

| 平台 | 曲目 | 有封面 |
|---|---|---|
| kw（酷我） | 20 首 | **0 张** |
| wy（网易云） | 20 首 | **20 张** |

酷我搜索接口根本不返回封面地址（`kw.ts` 里连 cover 字段都没有，
它的专辑图 URL 实测 404），所以酷我结果在界面上永远是灰度占位方块。

现在 `/api/search` 返回前，用**同一次搜索里**的 wy 结果按「标题+歌手」给其它平台补封面
—— 不额外发网络请求（wy 组本来就在本次搜索结果里）。
