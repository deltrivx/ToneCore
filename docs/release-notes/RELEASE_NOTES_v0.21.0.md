# ToneCore v0.21.0

> 统一音源状态口径；歌词支持偏移校准并解析 [offset:]；左右滑切歌加跟手动画。

## 修复一：音源「结果不统一」

### 现象

同一张音源卡片上，「不可用 · 0/2 成功 · 0%」和「测试结果：部分可用」
**同时显示且互相矛盾**。

### 根因

状态行把两套结论**并列**渲染了：

| 结论 | 来源 | 统计口径 |
|---|---|---|
| 自动健康度 | `healthDetail` | 后端累计的**真实取链**成功率 |
| 手动测试 | `testResults` | 用户点「测试」时的**单次探活** |

两者统计来源本就不同：一个源可能从没被自动选中过（历史成功率 0%），
但手动探活时是通的 —— 于是同一张卡上一边红一边绿。

### 修法

只出**一个**结论，优先级：

1. 有手动测试结果 → 以它为准（用户刚点的，最权威），并显示时间；
2. 否则 → 用自动健康度，附补充明细（累计 N/M 次取链成功）便于判断可信度。

配色也统一到同一个口径，不再出现同盒子内两种结论色。

## 修复二：歌词整首对不上（有前奏）

### 现象

用户指出：每首歌的歌词都对不上，**有前奏**的歌尤其明显。

### 根因

这不是「版本匹配错」（上一版已修），而是**系统性平移**：

歌曲有前奏（几十秒纯音乐），而歌词从第 0 秒就开始排。
于是整首歌词相对音频**整体提前**了一个前奏的长度 ——
错的是整体偏移，不是某一句，逐句改歌词治不好。

而代码里**此前完全没有偏移机制**（`offset` 只在 CSS 里作为 DOM 属性出现过）。

### 修法（两层）

**第一层 · 服务端解析标准标签**

LRC 有标准的 `[offset:xxx]` 全局偏移标签，酷我等源确实会输出 ——
实测歌词首行就是 `[offset:0]`，但**从未被解析过**。

- 新增 `parseLrcOffset()`，单位按标准为**毫秒**，正值表示整体**延后**；
- `parseLrc()` 末尾统一应用，再排序返回。

**第二层 · 前端手动校准**

很多源并不带 offset 标签，所以还需要用户侧兜底：

- `state.lyricOffset`（秒），正值 = 歌词提前，负值 = 歌词延后；
- 全屏播放页歌词区上方新增校准条（±0.5s / 重置）；
- **按曲目记忆**在 localStorage（每首歌前奏长度不同，错位量也不同），
  切歌时自动加载对应偏移。

> 有前奏的歌通常要**延后**，即点「+0.5s」。

## 变更：左右滑切歌加跟手动画

上一版已支持左右滑切歌，但没有视觉反馈。现在：

- 拖动时内容层**实时跟手**（位移 ×0.55 阻尼，越拖越沉）；
- 松手未达阈值 → 回弹归位；
- 确认切歌 → 整屏滑出 → 换曲 → 从反侧滑入；
- 新增**方向锁**：首次位移超过 8px 时判定，纵向占优即彻底放弃本次手势，
  避免与歌词区纵向滚动打架（此前只在结束时才判断，拖动过程中会误判）。
