## 新增一：系统媒体控件（锁屏）

### 现象

锁屏时手机自带的媒体组件只显示「ToneCore 音乐中枢」，
**没有专辑图、没有歌名、没有歌手、也没有播放控制**。

### 根因

`navigator.mediaSession` **完全没有实现**。浏览器在页面不主动上报时，
只能拿 `<title>` 兜底 —— 所以看到的就是页面标题。

### 修法

新增 `useMediaSession.js`，上报三块内容：

1. **metadata**：标题 / 歌手 / 专辑 / 封面 —— 锁屏直接可见；
2. **playbackState**：锁屏上的播放/暂停按钮状态同步；
3. **action handlers**：play / pause / previoustrack / nexttrack /
   seekbackward / seekforward —— 锁屏按钮与耳机线控可用。

两个实现要点：

- ⚠️ **封面必须给绝对 URL**：系统媒体控件不在页面上下文里取资源，
  传 `/cover/xxx.png` 相对路径会拿不到图（表现为锁屏没有专辑图）。
  模块内 `toAbsolute()` 负责补全。
- **artwork 给多尺寸**（96→512）：系统按自己需要挑，只给一张可能不显示。

不支持 `mediaSession` 的环境（如部分桌面浏览器）自动空转，
不会把播放逻辑拖挂。

## 新增二：歌词一键对齐

有前奏的歌，歌词从第 0 秒开始排、实际人声晚 N 秒，
于是歌词全程领先 —— 就是「歌没放完，歌词已经跑完空白」。

手动 ±0.5s 估算太笨。现在点「**对齐**」即可一次到位：
听到某句正在唱时点一下，把该行对齐到此刻。

推导：`syncLyricIndex` 用 `t = currentTime + offset` 匹配行，
要让第 i 行此刻正好高亮，即 `now + offset = lines[i].time`，
故目标 `offset = lines[i].time - now`。

校准条同时把「提前 / 延后」的语义写清楚：
- 歌词比唱的**慢** → 点「提前」
- 歌词比唱的**快**（有前奏） → 点「延后」

## 修复一：滑动切歌改动过大

上一版把手势挂在**整页根节点**上并平移整个内容层，
导致播放界面整体抖动，还与歌词区滚动、进度条拖动互相打架。

按用户要求收窄：**手势与位移只作用于专辑图（大碟）**，
其余区域完全不响应，页面不再抖。

- 拖动中（`dragActive`）不加 transition，才能实时跟手；
- 松手后恢复 transition，回弹或滑出；
- 方向锁保留：首次位移超 8px 判定，纵向占优即放弃本次手势。

## 修复二：歌词比歌曲先跑

`syncLyricIndex` 里原本有 `+0.25s` 的「跟手」提前量。

有前奏的歌歌词本就从第 0 秒排，再提前只会让歌词跑得更快 ——
正是「歌还没放完、歌词已经跑完空白」的成因之一。**已移除**。
