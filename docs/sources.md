# 音源管理

ToneCore 的取链能力有两条通道：

| 通道 | 说明 | 依赖 |
|---|---|---|
| **内置直连** | 宿主自研，目前覆盖酷我（kw） | 无，保底能力 |
| **音源脚本** | 洛雪音乐格式的 `.js` 脚本 | 社区维护 |

取链时先用内置直连，失败再回退到音源脚本（多脚本并行，谁先成功用谁）。

> **搜索不走脚本**：洛雪脚本只提供取直链能力（`action=musicUrl`），
> 搜索由宿主自研的各平台接口完成。这是 LXServer / lxmusic 等项目的通行做法。

## 放置位置

```
/data/sources/
├── 六音音源.js
├── 野花🌷.js
└── ...
```

放好后在「音源」页面点「重新加载」，或在界面里直接粘贴脚本内容导入。

## 平台与优先级

默认 `kw,kg,tx,wy,mg`，可在设置页调整顺序：

| 标识 | 平台 |
|---|---|
| `kw` | 酷我 |
| `kg` | 酷狗 |
| `tx` | QQ 音乐 |
| `wy` | 网易云音乐 |
| `mg` | 咪咕音乐 |

顺序只在**评分相同时**作为参考，不会让低分候选插队 ——
选源以跨平台打分结果为准（见 README「为什么音源要统一打分」）。

酷我（kw）有内置直连通道，建议保持靠前。

## 健康度与熔断

每个脚本的成功率与平均耗时都会被记录，健康分高的优先使用。
**连续失败 ≥ 3 次**的脚本会被临时熔断跳过，避免每次都白等一轮超时。

「音源」页面可以看到每个脚本的加载状态、成功 / 失败次数与失败原因。
加载失败的脚本同样会列出并附上原因，不会静默消失。

## 启停与删除

- **停用**：脚本移入 `/data/_disabled/`，不再加载，可随时启用回来
- **删除**：脚本移入 `/data/_trash/`（带时间戳前缀），可手工找回

两者都不做硬删除。

## 音源可用性

音源脚本由社区维护，可能因上游风控失效。建议：

- 同时放 3~5 个音源，引擎会自动降级
- 定期看「音源」页面的健康度与失败原因
- 用「测一下」按钮单源验证，返回结果里会给出具体失败原因
- 失效的脚本直接停用或删除

## 安全提示

音源脚本是可执行 JS，**只放你信任的来源**。脚本在沙箱中运行，
但仍建议审阅后再使用。
